# 测试计划

## 1. 测试目标

验证系统能否准确识别不同兼职场景，生成与岗位相关的风险追问和风险报告，避免出现明显不相关的问题。

## 2. 测试范围

1. Chrome 插件页面输入。
2. 当前网页文本抓取。
3. 后端风险检测接口。
4. Agent 追问接口。
5. 历史记录接口。
6. 规则管理接口。
7. 大模型 API 关闭和开启两种情况。

## 3. 重点测试场景

| 场景 | 测试重点 |
|---|---|
| 家教兼职 | 不应提示刷单；应关注家长/机构身份、课时费、上课地点 |
| 短期会务 | 不应追问试用期、周结、月结；应关注主办方、考勤和当天工资 |
| 气氛充场 | 应关注工作边界、是否陪酒、返程安全 |
| 线上兼职 | 应重点识别刷单、垫付、充值、返利 |
| 门店服务 | 应关注门店主体、排班、服装费、押金 |
| 信息模糊 | 应主动追问主体、内容、工资、地点 |

## 4. 验收标准

1. 插件可以正常加载。
2. 后端服务可以正常启动。
3. `/api/analyze` 可以返回结构化结果。
4. Agent 追问与岗位类型相关。
5. 高风险文本可以命中对应风险。
6. 历史记录可以查询。
7. 规则接口可以新增、修改、删除规则。
8. 文档、截图和测试记录齐全。
