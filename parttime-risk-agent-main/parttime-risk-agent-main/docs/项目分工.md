# 五人分工方案

| 成员 | 角色 | 主要职责 | 具体任务 | 主要产出 |
|---|---|---|---|---|
| 成员1 | 组长 / 项目负责人 | 统筹项目进度、控制项目范围、协调成员开发、审核最终成果 | 制定项目计划和WBS；分配任务；管理GitHub仓库；创建Issue；审核Pull Request；协调接口变更；参与关键修改；组织答辩 | 项目计划、WBS、进度表、风险表、会议记录、答辩PPT框架、最终整合版本 |
| 成员2 | 后端开发 | 负责系统服务能力，为前端和Agent提供接口支持 | 搭建Express后端；实现风险检测接口；实现Agent追问接口；实现历史记录接口；实现规则管理接口；实现大模型API中转；维护数据库连接；同步更新接口文档 | 后端代码、接口文档、数据库脚本、API测试截图、后端运行说明 |
| 成员3 | 前端开发 | 负责Chrome插件端页面展示和用户交互，与后端接口对接 | 实现插件弹窗页面；展示招聘文本、岗位类型、风险等级、风险分数、Agent追问、用户补充回答、最终报告；展示历史记录；调用后端接口 | Chrome插件页面、交互逻辑、接口调用代码、页面截图、前端使用说明 |
| 成员4 | Agent与规则设计 | 负责兼职风险判断逻辑、规则设计、评分标准和大模型提示词优化 | 设计岗位分类规则；整理风险关键词；设计风险评分标准；优化Agent追问逻辑；设计大模型prompt；根据测试反馈调整规则；提供典型兼职案例 | 风险规则库、评分标准文档、Agent流程设计、Prompt文档、案例库 |
| 成员5 | 测试与文档 | 负责系统测试、文档整理和验收材料 | 编写需求规格说明书；编写用例说明；编写测试用例；执行功能测试、边界测试、异常测试；记录测试结果；整理项目截图；编写用户手册和项目总结 | 需求文档、用例文档、测试用例表、测试报告、用户手册、项目总结 |

## 协同原则

1. 后端新增或修改接口前，必须先更新接口文档。
2. 前端根据接口文档进行页面开发和接口调用。
3. Agent规则变化需要同步给后端和测试成员。
4. 测试成员根据每次新增功能补充测试用例。
5. 组长负责确认接口文档、前端展示、后端返回和测试结果一致。
