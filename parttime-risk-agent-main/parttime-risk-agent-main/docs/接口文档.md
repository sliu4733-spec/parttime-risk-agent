# 接口文档

后端默认地址：

```text
http://localhost:3000
```

## 1. 健康检查

```text
GET /api/health
```

返回示例：

```json
{
  "ok": true,
  "service": "parttime-risk-agent-server"
}
```

## 2. 风险检测接口

```text
POST /api/analyze
```

请求：

```json
{
  "text": "9.6号需要1个兼职，工作时间8:00-18:00，工资130/天，地址明宇尚雅酒店"
}
```

返回：

```json
{
  "ok": true,
  "recordId": "record-xxx",
  "needQuestion": true,
  "extracted": {
    "jobType": "短期活动/会务协助",
    "durationType": "短期/临时"
  },
  "questions": [
    "请确认活动主办方、酒店对接人或招聘方身份，是否能核实真实负责人？"
  ]
}
```

## 3. 用户补充回答接口

```text
POST /api/follow-up
```

请求：

```json
{
  "text": "原始兼职招聘文本",
  "followUp": "用户对Agent追问的补充回答"
}
```

作用：将原始文本和用户补充信息合并后重新分析。如果仍缺少关键信息，继续返回追问；如果信息足够，返回风险报告。

## 4. 历史记录接口

```text
GET /api/history
```

作用：查询最近检测记录。

## 5. 单条历史详情接口

```text
GET /api/history/:id
```

作用：查询某一次检测的完整输入、追问、报告和时间。

## 6. 查询规则接口

```text
GET /api/rules
```

作用：查询系统当前风险规则。

## 7. 新增规则接口

```text
POST /api/rules
```

请求：

```json
{
  "category": "先交费用",
  "name": "押金风险",
  "keywords": ["押金", "保证金"],
  "score": 40,
  "description": "招聘方要求先交费用，存在骗取钱款风险。",
  "advice": "未核实前不要缴费。"
}
```

## 8. 修改规则接口

```text
PUT /api/rules/:id
```

## 9. 删除规则接口

```text
DELETE /api/rules/:id
```
