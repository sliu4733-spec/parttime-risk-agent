# 兼职岗位风险检查 Agent Chrome 插件

这是一个面向大学生兼职求职场景的浏览器插件式 Agent。用户打开兼职招聘网页后，点击插件即可抓取当前页面文本，检测押金、培训费、刷单、垫付、薪资异常、隐私索取等风险；当信息不足时，Agent 会主动追问用户补充信息，并生成结构化风险报告。

## 核心功能

1. 分析当前网页兼职信息
2. 手动粘贴招聘文本检测
3. Agent 主动追问缺失信息
4. 用户多轮补充后的动态二次风险分析
5. 风险等级、评分、证据片段和建议报告
6. 风险分值明细和命中规则展示
7. 招聘信息缺失项提示
8. 给招聘方的建议追问清单
9. 页面风险词高亮和清除高亮
10. 检测历史保存和清空
11. 风险规则维护
12. 风险报告复制和 txt 导出
13. 可选大模型 API 生成场景化追问和解释报告

## 本地加载方式

1. 打开 Chrome 或 Edge 浏览器。
2. 地址栏输入 `chrome://extensions`。
3. 打开右上角“开发者模式”。
4. 点击“加载已解压的扩展程序”。
5. 选择本项目文件夹 `parttime-risk-agent-extension`。
6. 打开一个包含兼职招聘信息的网页，点击浏览器右上角插件图标。

## 使用方式

### 方式一：分析当前页面

1. 打开兼职招聘网页，也可以打开 `examples/test-job.html` 测试示例页面。
2. 点击插件图标。
3. 点击“分析当前页面”。
4. 如果 Agent 追问信息，填写补充回答。
5. 如果 Agent 判断仍缺少关键条件，可以继续补充回答，不限制只能回答一次。
6. 查看风险报告。
7. 查看命中风险、缺失信息、分值明细、建议追问和证据片段。
8. 点击“高亮风险词”，可在当前页面标记风险文字。
9. 点击“导出报告”，可保存 txt 风险报告。

### 方式二：手动粘贴检测

1. 点击插件图标。
2. 在文本框中粘贴招聘信息。
3. 点击“检测输入内容”。
4. 查看 Agent 追问或最终报告。

## 大模型 API 设置

插件默认使用本地规则 Agent，不需要联网和 API Key。

如需启用真实大模型：

1. 点击弹窗右上角“规则”。
2. 勾选“启用真实 API 生成追问和解释报告”。
3. 填写接口地址、模型名称和 API Key。
4. 保存设置。

注意：课程演示可以临时在插件中保存 Key。正式产品不应把 API Key 放在浏览器插件中，应使用后端中转服务。

## Agent 流程

```text
用户点击分析
  ↓
popup 发送任务
  ↓
background 请求 content-script 抓取网页文本
  ↓
background 运行风险规则扫描
  ↓
判断信息是否缺失
  ↓
缺失：优先调用大模型生成场景化追问；API 关闭或失败时使用本地规则兜底
  ↓
用户补充回答
  ↓
如果仍缺信息，继续追问
  ↓
二次分析
  ↓
生成风险报告
  ↓
popup 展示结果，content-script 高亮风险词
```

## 判断逻辑说明

Agent 的追问不是固定模板，而是按三层逻辑生成：

### 1. 先识别兼职岗位类型

系统会根据招聘文本中的关键词判断岗位类型：

| 岗位类型 | 识别关键词示例 | 追问重点 |
|---|---|---|
| 家教/补习 | 家教、补习、辅导、年级、语数英、课时 | 家长/机构身份、课时结算、上课地点安全、是否有中介费 |
| 门店服务 | 服务员、收银、传菜、餐饮、奶茶、门店 | 门店名称、排班、试用期工资、服装费或押金 |
| 地推促销 | 派发、传单、地推、促销 | 活动主办方、集合地点、计件规则、物料押金 |
| 配送/跑腿 | 外卖、配送、跑腿、骑手、快递、分拣 | 平台/站点、车辆装备、保险责任、装备押金 |
| 校园助理 | 助教、助理、图书馆、实验室、勤工助学 | 招聘主体、工作内容、补贴发放、是否占用上课时间 |
| 线上兼职 | 线上、手机操作、任务、打字、录入 | 是否刷单垫付、是否充值返利、是否索要敏感信息 |
| 活动充场/气氛组 | 充场、气氛组、坐着玩、酒水、表演、鼓掌 | 工作边界、是否陪酒/拉客/营销酒水、现场安全、返程、结算扣款 |
| 短期活动/会务协助 | 酒店、会议、会务、PPT、播音、宣讲、签到、接待 | 主办方/负责人、当天工资、考勤、设备要求、是否额外收费或垫付 |
| 未明确 | 无明显岗位类型 | 按通用兼职规则追问公司、工作、薪资、地点、结算和费用 |

### 2. 再提取通用关键信息

系统会检查招聘文本是否已经说明以下信息：

- 招聘主体：公司、店铺、机构、家长、学校部门等；
- 工作内容：岗位职责、家教科目、门店岗位、地推任务等；
- 薪资标准：如 70 元一小时、日结 300、时薪 20 等；
- 结算方式：日结、周结、月结、课后结等；
- 工作地点：线上、校内、具体地址、门店地点等；
- 额外交费：押金、培训费、服装费、资料费、报名费等；
- 垫付刷单：刷单、充值、返利、先付款、任务单等；
- 联系方式：微信、QQ、电话、私聊等。

### 3. 最后按岗位类型生成追问

如果某些关键信息缺失，Agent 会结合岗位类型生成对应追问。例如：

- 家教岗位不会追问“是否手机操作”，而会追问“家长/机构身份、课时如何结算、上课地点是否安全”；
- 门店岗位会追问“排班、试用期工资、服装费、门店名称”；
- 线上兼职会重点追问“刷单、垫付、充值、验证码、银行卡”等风险；
- 地推促销会追问“集合地点、主办方、计件规则、物料押金”。
- 活动充场/气氛组会追问“工作边界、酒水是否自愿、是否陪酒或营销、返程安排、负责人和扣款规则”，不会追问刷单、手机操作或试用期。
- 短期活动/会务协助会追问“活动主办方、酒店对接人、当天工资是否完整、考勤方式、设备费/服装费、活动结束后工资发放时间”，不会追问周结、月结、试用期或刷单。

这样做的目的是避免 Agent 使用同一套问题问所有兼职，使追问更符合实际场景。

### 4. 风险字段不混用

同一个底层检查项在不同岗位中会使用不同显示文案：

- 家教/补习：显示为“是否需要预付、垫付或购买资料”，不显示“刷单”；
- 门店服务：显示为“是否需要垫付物料或提前转账”；
- 地推促销：显示为“是否需要垫付物料费用”；
- 配送/跑腿：显示为“是否需要垫付装备或订单费用”；
- 线上兼职：如果文本涉及任务返利、充值、做单，才显示“刷单、垫付、充值或返利”。
- 活动充场/气氛组：显示为“是否需要押金、报名费、入场费或强制消费”，重点检查工作边界和现场安全。
- 短期活动/会务协助：如果原文写明具体日期、当天工资和工作时间，系统不会再追问“日结、周结还是月结”，而会追问当天工资发放时间、考勤和扣款规则。

如果启用了大模型 API，Agent 会把招聘原文、岗位类型、已提取信息、缺失字段和规则命中结果一起传给模型，要求模型只生成与当前岗位相关的问题。大模型输出失败时，系统会自动回到本地场景化规则，保证插件仍可使用。

这样可以避免把某一类兼职的风险话术套到另一类兼职上。例如家教信息中写明“70 元一小时”，系统会识别为课时费，不会把“费用”误判为押金或培训费；如果没有出现刷单、返利、充值等词，也不会在家教报告中提示刷单风险。

## 多轮追问机制

插件不是“一次追问后直接结束”。每一轮用户补充回答后，background service worker 会把原始招聘文本和所有补充回答合并，再重新执行：

1. 岗位类型识别；
2. 关键信息提取；
3. 风险规则扫描；
4. 缺失字段判断；
5. 场景化追问生成或最终报告生成。

如果仍然缺少关键判断条件，Agent 会继续追问；如果信息足够，或者已经命中明显高风险规则，Agent 才生成最终风险报告。这样可以体现任务型 Agent 的动态决策能力，而不是固定表单流程。

## 课程答辩说明

本项目不是完整招聘平台，也不是普通网页检测器，而是 Chrome 插件式任务型 Agent。它的 Agent 特征体现在：

- 能读取当前网页内容，具备环境感知能力；
- 能调用风险规则扫描工具；
- 能判断信息是否完整；
- 能主动追问用户补充信息，并支持多轮连续补充；
- 能结合多轮补充回答进行动态二次分析；
- 能生成可解释风险报告并高亮风险证据。

## 答辩可展示功能点

建议答辩时按以下顺序演示：

1. 打开示例兼职网页。
2. 点击插件并选择“分析当前页面”。
3. 展示 Agent 生成的风险报告。
4. 展示“命中风险”“缺失信息”“分值明细”“建议追问”。
5. 点击“高亮风险词”，展示原网页风险词标记。
6. 点击“导出报告”，展示报告可保存。
7. 输入模糊兼职信息，展示 Agent 主动追问。
8. 分多次补充回答，展示 Agent 会继续追问，直到信息足够或命中明显风险。
9. 打开“规则”页面，新增一个风险规则，展示规则可维护。
10. 回到弹窗查看最近检测记录，展示结果可追溯。
