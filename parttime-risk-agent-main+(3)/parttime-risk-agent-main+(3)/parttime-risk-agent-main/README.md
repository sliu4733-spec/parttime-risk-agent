# 兼职风险检查 Agent V3 本地联调版

此目录是独立测试版本，没有推送 GitHub。保留用户自带大模型 API：插件直接识图和分析，Express 后端只负责账号、SQLite 持久化、个人历史与会话同步。不包含案例库、管理员审核或统一模型额度。

## 本机启动

1. 安装 Node.js 20 或更高版本（当前电脑已安装）。双击 `启动后端.cmd`，保持启动窗口运行。也可在 `server` 目录执行 `npm ci`、`npm start`。
2. 浏览器访问 `http://127.0.0.1:3000/api/health`，应显示 `ok: true`。
3. Chrome 的 `chrome://extensions` 或 Edge 的 `edge://extensions` 开启开发者模式，加载本目录下的 **extension**。名称为“兼职风险检查 Agent V3 本地联调版”，版本 3.0.6。关闭旧版插件以免混淆。
4. 在插件“规则”页面配置你自己的 API，勾选启用后保存。新浏览器需重新配置，不同步 Key。
5. 打开插件先看到首页，可选择：**以游客模式使用**（无需账号，数据仅存本机）、**登录账号**或**注册账号**（后端地址默认 `http://127.0.0.1:3000`）。注册成功后回到登录页，用刚注册的账号（用户名 3–32 位，密码 8–128 位）登录后进入分析页。
6. 在分析页点击“分析当前页面”、粘贴文字点“检测输入内容”或“识别截图”，逐题回答；回答期间可点“按现有信息生成报告”结束本轮。报告生成后可复制、导出（下载 txt），点“开始下一轮检测”进行新一轮。结果和输入中的答案会保存在本机。勾选同意上传，再点击“同步当前记录 / 重试”，才会发送招聘文本、问答和报告。
7. 在另一浏览器加载同一扩展、登录同一账号，点击“下载云端记录”，在列表点击“打开 / 继续”。查看报告不需模型 Key，继续分析需本浏览器配置有效 Key。

“云端”按钮指当前填写的后端。在本机或局域网运行只用于课程联调，不代表已部署到公网。不需要购买云服务器。

## 局域网演示

服务端电脑启动 `启动局域网后端.cmd`；另一台电脑与其在同一局域网，将插件后端地址填为 `http://服务端电脑的局域网IP:3000`，例如 `http://192.168.1.20:3000`。服务端可用 `ipconfig` 查看 IPv4 地址；防火墙只对可信专用网络允许相应端口。另一台电脑不能填写 127.0.0.1（那代表它自己）。

只使用可信局域网和测试账号。当前默认 HTTP 无传输加密；公网部署需要 HTTPS、运行监控、备份和容量评估，尚未纳入本次测试。服务端电脑关机后同步停止，但插件可继续使用本地规则或用户 API 检测。

## 保存 同步 与冲突

- 未登录使用访客本机空间，登录后按“服务器地址＋账号”隔离记录。访客记录不自动转入账号空间。打开插件始终先显示首页，选择进入方式；分析页可随时通过账户栏“登录 / 注册”或“退出账号”切换。
- 插件只在用户点击同步时上传当前记录，不后台批量上传历史。API Key、模型配置、密码和截图原文件不随记录同步。截图识别文字会在用户选择同步时上传。
- 关闭弹窗后再次打开默认开始新一轮，历史中的“打开 / 继续”可恢复已保存会话和逐题输入；分析请求已发出时，后台完成后保存结果。关闭浏览器会中断尚未完成的网络请求，需重新检测。
- 后端不可用时，本机数据保留；服务恢复后点击同步重试。服务器使用记录版本和请求标识避免重复写入。
- 另一端已更新或删除时，上传被拒绝；点击下载显示冲突。选择“采用云端版本”会先保留一份未同步的本机副本，不静默丢弃本机修改。
- 列表“删除云端及本机记录”会校验版本。另一端下载后看到删除结果；旧版上传不会自动复活记录。冲突保留的本机副本只有用户主动上传才会成为新记录。
- “清空本机”仅清理当前空间的缓存，不删除服务器数据；未同步的修改会丢失。退出账号会隐藏该账号的数据，但保留设备本地缓存供下次登录使用；共享电脑可退出前清空本机。
- 登录令牌有效期七天，在线退出会立即撤销。离线退出清除本地凭证，无法立即撤销服务器令牌。

## 数据和实现

数据库位于 `server/data/sync.sqlite`，由 sql.js 执行 SQLite SQL，并在每次成功写操作时导出到临时文件后替换数据库文件。适用于单进程课程规模；不要让多个后端进程同时打开同一文件。备份时停止服务再复制该文件。

数据库表：users（账号与 scrypt 密码哈希）、sessions（哈希后的随机令牌及有效期）、records（账号归属、会话 JSON、版本、删除标志和最后写入标识）。服务端逐请求校验身份及所有权。

原本独立插件的分析流程仍在 `extension/background/service-worker.js`。新增 `background/sync.js` 处理同步，`popup/sync-ui.js` 处理账号与个人记录界面。此目录不依赖仓库中的旧 server 或嵌套 extension。

## 测试步骤

1. 打开插件确认先显示首页：游客模式、登录、注册三个入口；以游客模式进入分析页检测并保存，关闭再打开插件，重新进入分析页后应为空白；手动从历史选择“打开 / 继续”才能恢复问题和未提交答案。
2. 注册账号 A，确认注册后回到登录页；登录 A 后进入分析页，检测、同步；在 Edge 登录 A，下载并打开记录。
3. 注册账号 B，确认不能看到 A 的历史。
4. 关闭、重启后端，再下载记录，验证 SQLite 持久化。
5. 两个浏览器修改同一条记录，先后上传，确认后上传者获得冲突提示；采用云端时本机修改另存副本。
6. 一端删除，另一端下载，确认删除生效且旧副本不能覆盖云端。
7. 停止服务，继续本地检测，确认同步失败不丢本机内容；重启后重试。
8. 检查识图、针对性追问、三轮限制、薪资日结、高亮、复制/导出报告、“开始下一轮检测”与旧版一致；分析期间界面有进度提示，不再长时间无反应。

自动检查：在 server 目录执行 `npm test`；另运行 `node ../extension/regression-test.cjs` 检查原有分析流程。自动测试使用独立临时数据库，不访问用户的真实 API。

## 3.0.4 修复说明

分析流程：读取原文或图片文字 → 大模型按语义抽取岗位事实 → 本地规则检查 → 大模型选择至多三条相关追问 → 结合用户回答重新分析 → 基于证据生成报告。Agent 的问题只提供问答上下文，不作为招聘事实参与正则抽取。模型明确留空的字段保持未知，不被宽泛关键词填回。日薪不等于日结。

截图不要求“招聘”关键词。空输出和错误的“暂无招聘信息”判断会重试；仅有模型推理内容不视为 OCR 原文，截断会要求分段截图。报告要求区分原文、自述和待核实项；规则分数与模型补充疑点分开解释，不冒充联网核验。

重新进入分析页默认清空本轮，保留个人历史供手动打开。使用浏览器扩展管理页重新加载本目录 extension，确认显示 v3.0.4。API 模型仍须支持图片输入，自动测试使用模拟模型响应，不代表真实截图识别率验证。

## 3.0.5 当前岗位详情抓取

修复“分析当前页面”读取整个 main/body、混入导航和左侧岗位列表的问题。现在优先读取用户选中的正文，其次定位可见的岗位详情容器及职责/任职要求区域。过滤导航、按钮、推荐岗位和隐藏旧面板，保留段落及详情滚动区域中的正文；每次点击重新读取 DOM。没有明确详情或多个候选难以区分时提示用户选择目标正文，不再回退到整页。

结果上方显示分析来源，招聘信息框展示实际送入分析的文本；即使直接生成报告也保留原文。岗位分类允许 AI 产品经理等真实专业岗位，不强制归入兼职分类。

升级后重新加载 extension，并刷新已经打开的招聘网页，以替换旧 content script，确认插件 v3.0.5。测试覆盖仿照视频的分栏布局、隐藏旧详情、切换岗位、通用正文、多个候选、选择正文和滚动区域。尚未对登录态 BOSS 直聘真实 DOM 做浏览器实测；不同网站结构、iframe 或未加载详情可能需要选中文字或截图。

## 3.0.6 证据驱动的动态分析

修复无人配送车产品经理误归为配送员，以及 K/万薪资区间和多薪格式漏识别。模型正常时，追问和报告由当前原文与问答动态生成，允许预设列表以外的新主题。最终报告不再将岗位模板的建议和缺失项作为模型底稿；输出事实、分析、问题各自携带原文引文，代码校验引文存在、过滤重复已知薪资和无关问题。问题中的假设不作为事实证据。

模型提示要求按实际职责与交付物理解职业，而不是按行业词套分类。未改动用户选择的模型或 API Key；提示词无法提升模型本身的能力上限。证据校验只能检验引用存在，不能保证所有语义推断正确。

界面明确显示事实抽取/报告是否由模型完成。HTTP 失败、超时、空输出或证据格式无效均显示降级，不将本地结果冒充模型结果。自动测试使用模拟响应；真实 API 的网络、账户权限和模型效果仍需在浏览器重新检测后确认。

原“综合评分”改为“规则风险分”，是命中规则分值的累加，无固定满分，不是岗位好坏或诈骗概率；越高代表规则风险线索越多/越严重。0分只表示没命中计分规则，不表示安全。默认30分、60分分别为中高风险阈值，先交费用和刷单垫付类别可直接判为高风险。模型额外分析不冒充计入该分数。

加载 extension v3.0.6 后刷新招聘网页，重新检测。历史中的旧报告保留原内容，不会自动重新分析。
